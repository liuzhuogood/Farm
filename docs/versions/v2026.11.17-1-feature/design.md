# v2026.11.17-1-feature 设计

## 目标

为 Farm 桌面端补全应用内更新体验：原生菜单与托盘可手动检查更新，系统设置可控制启动检查与自动安装，发现新版本时在主窗口底部以简洁提示呈现，点击进入统一更新弹窗，并在弹窗内提供 GitHub 发布页入口。

## 关键决策

- **入口**：macOS 主菜单 `Farm` 与托盘菜单同增“检查更新…”项，共用 `check-update` 事件：先显示并聚焦主窗口，再通知前端打开弹窗并检查版本。二者行为一致，避免出现两个不同实现。
- **设置**：系统配置“通用设置”新增“检查更新”“自动更新”两个开关，持久化于 localStorage（`farm.update-settings`）。关闭“检查更新”时“自动更新”同步关闭并禁用；非法存储值回落默认（检查开、自动关），不猜测未知字段。
- **启动检查**：应用启动时按设置检查一次；仅当“检查更新”开且“自动更新”开、且存在可安装更新时自动安装，否则只提示。
- **提示形态**：移除首页顶栏的更新标签（版本胶囊与 New 徽标），改为底部胶囊提示，仅在检测到新版本时出现；点击打开更新弹窗。
- **弹窗**：统一为“软件更新”单一标题，左下角提供 GitHub 发布页链接，右侧按状态给出“稍后提醒 / 立即更新 / 检查更新 / 确定”。
- **错误收敛**：桌面更新器把 `ReleaseNotFound`、`TargetNotFound(s)` 转成用户可读原因而非抛出，其余错误才抛出。

## 修复

- 弹窗通过 X 或 Esc 关闭时统一走 `closeDialog()`，使“稍后提醒”语义成立，底部提示不会立即重现。
- 每轮检查重置升级进度为 `idle`，避免失败后再次检查仍显示上一次的失败进度条。

## 边界与风险

- macOS 更新包依赖发布流水线的 `TAURI_SIGNING_PRIVATE_KEY` 生成 `.app.tar.gz` + `.sig`；Apple 系统签名与公证未配置时使用 ad-hoc 签名，不宣称通过正式签名。
- 首次使用新更新能力必须安装一次含新更新器与公钥的完整包，旧版无法凭空获得该流程。
- 桌面菜单事件在 SPA 尚未挂载时可能无人接收，验证脚本因此等待页面就绪；该时序依赖已记录，未引入重试机制。
