# v2026.11.19：双连接设备归并（同一台机 USB + 无线 adb 合成一个条目）

## 1. 版本定位与概述

在 `v2026.11.16` 基线上，解决同一台手机同时插 USB、又开无线调试时被 `adb devices` 当成两台设备的问题：按设备自身身份归并为一个条目，并在条目上表达“有几种连接方式、各自是否在线、当前走哪条”。

本版先设计、先原型，再分步实现。界面已按项目原型技能做可运行原型，用户 2026-11-19 选定**方案一 并列图标**，之后才进入正式实现。

- 设计文档：[designs/2026-11-19-dual-link-device-merge.md](../../designs/2026-11-19-dual-link-device-merge.md)
- 实施跟踪：[tasks.md](tasks.md)
- S1 任务书：[s1-brief.md](s1-brief.md)
- 原型：`prototypes/cases/dual-link-device-v1`（定稿）、`dual-link-device-v2`（仅留档）；截图 `prototypes/artifacts/dual-link-device-v1|v2/`

## 2. 已确认的决定

| 项 | 结论 |
| --- | --- |
| 卡片方向 | 方案一：两个等权图标块并列，当前通道彩色填充，另一路描边；只用图标不写“USB/无线”文字；不使用手动切换 |
| 通道选择 | 自动，USB 优先；USB 不可用时走无线；不提供切换交互 |
| 归并键 | `ro.serialno` → `ro.boot.serialno` → `android_id`（前缀 `hw:` / `aid:`）；取不到不合并，标 `pending` |
| 对外接口 | `serial` 语义不变，仍为“当前通道 serial”；新增 `identity` / `identity_source` / `connections[]` / `active_kind` |
| A 自动化口径 | 改：`/api/automation/devices` 与 MCP `phone_devices` 改为“一行一设备”，同步更新 `/fram.skill` |
| B 历史记录 | 任务历史与操作日志只加 `identity` 列，不回填历史 |
| C 数据存储 | 新增 `device_channels` / `device_identities`，老 `devices` 表继续承担手动登记，迁移可回滚 |
| D 重复通道 | 同一身份的同类重复通道（`IP:端口` 与 `adb-序列号-后缀`）不在界面列出，只取最新一条 |

## 3. 范围

本版包含 S1–S6（详见 [tasks.md](tasks.md)）：身份采集与接口字段、后端按身份归并、前端卡片与本地偏好迁移、详情页连接面板、数据库迁移、自动化/MCP 口径与文档。

不包含：手动切换通道、连接质量/带宽展示、多设备分组、iOS/鸿蒙等非 adb 通道。

## 4. 验收

按设计文档第 9 节 T1–T12 由农场测试员执行；S1 先验身份一致性与 `pending` 两种状态，S2 起逐步覆盖其余用例。每步验收通过才进入下一步，未过退回说明差在哪。
